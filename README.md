# Vana

一个 iOS 26 的健康对话 app。打开就是聊天界面,没有仪表盘——你问「我最近睡得怎么样」,它自己去
Apple Health 里查睡眠数据,再把结论讲给你听。

拍一张纸质化验单,它在本机把字认出来再讨论；你说「我不能吃布洛芬」,它记下来,以后每次建议都
绕开它；你早上收到的那条通知里写的是结论,不是「该打卡了」。

> 仓库名和工程名还叫 HealthChat,app 显示的名字是 **Vana**。换掉工程名会让已存的 API key 和
> 已授权的健康数据全部对不上,不值得。

**这是个自带钥匙的 app**:所有模型调用都发给**你自己**配置的云端 provider(设置页里填 API key),
没有服务器,没有账号,没有订阅。

---

## 它能做什么

**读你的健康数据并解释它。** 步数、睡眠、心率与 HRV、锻炼、体重与体成分、血压、体温血氧,
还有你已经连到「健康」App 的化验和体检记录。模型自己决定查什么、查几天,回复上方标注这一轮
查了哪些数据,结果面板里能展开看逐小时的图。

**打开就有一句话。** 第一屏不是先问你一个问题,而是先说发生了什么:「昨晚只睡了 6.2 小时,
比最近常态少 100 分钟」。这句话本地算出来立刻显示,模型润色好了再原地换掉——没配 key 也有。

**拍照读化验单。** 拍纸质化验单、药瓶、成分表,或者选相册里已有的照片、医院导出的 PDF /
Word / txt。**文字识别全在本机做,发出去的只有文字,照片不离开这台设备**——一张化验单上有姓名、
就诊号、医院、医生签名,而这次对话只需要那几行数值。发送之前每一张都点得开、改得动。

**记住关于你的事。** 「我睡够 7 小时才算好」「跑步伤膝盖」这类会一直成立的话会被记下来,进
每次对话的开场。**不记数字**——「昨晚睡了 6.2 小时」明天就是错的。设置页里每一条都能看、能改、
能删,还标着这句话是你手写的、你让它记的,还是它自己抽的。

**用药与补剂表。** 在吃什么、需要时吃什么、试过什么没用、什么不能吃。最值钱的一列是「效果」,
不是剂量——它不是打卡本(Apple Health 已经有完整的用药追踪了),它记的是那次判断和后来的结果。
「不能吃」的那组永远排在模型看到的第一行。约好两周后回访,到期那天早上它会来问一句。

**记得上次聊过什么。** 你说「上次你说的那个方法」,它会去翻以前的会话把当时的结论找回来,
而不是重新猜一遍。只在你自己提起过去时才会这么做。

**早晚的 check-in。** 时间自己定。通知正文是当天数据里真的有点意思的那件事,不是固定文案;
到期的回访、长期目标的周进展也走这里,而且是**已经跑出结论**的那句话。

**Siri。** 「问 Vana 昨晚睡得怎么样」——不需要 Apple Intelligence,本地算完直接念。
「问 Vana …」会把 app 拉起来走完整的对话。

**家庭成员。** 给家人各建一份完全隔离的数据(会话、记忆、用药表、化验单各自一套)。
Apple Health 归机主那个成员——切到家人时健康工具整个不出现,因为那本来就不是她的数据;
她那边靠化验单、用药表和聊过的内容回答。

**隐私对话。** 一条不留本机痕迹的会话:不存会话文件、不抽记忆、不落照片。它照样认得你
(读记忆),但什么都不写下来。图标用的是 `eye.slash` 不是锁——问题终究要发给你配置的云端
模型才有人回答,这一点首屏就写着。

**其余几样。** 上网查它不知道的事(需要另外一把 serper.dev 的 key,不填就不出现);
只到城市的粗定位(季节、气候、时差、当地就医方式);五种说话风格(均衡 / 数据派 / 教练 /
陪伴者 / 直说);回复还在写的时候可以接着说下一句,它会在下一个工具轮接住。

## 隐私

- **健康数据只读**,一个字都不写回 Apple Health(DEBUG 构建里那个生成模拟数据的按钮是唯一
  一处写入,正式构建里整段代码都不编译进去)。
- **API key 只进 Keychain**,不落 UserDefaults、不进任何日志。
- **照片和文件不出本机**,发给模型的只有识别出来的文字。
- **没有后端**。除了你自己配的模型服务(和可选的搜索服务),这个 app 不连任何服务器,
  没有埋点、没有分析 SDK。
- **位置只到城市**,坐标一个字都不进 prompt;授权面板里连「精确位置」的开关都不露出来。
- 会话、记忆、用药表、化验单都存在 app 自己的沙盒里,化验单和用药表用
  `.completeFileProtection`。
- 但要说清楚:**你的问题和查到的健康聚合值会发给你选的那家云端模型**。这一点是这类 app
  的地基,含糊其辞才是真的逗人玩。

## 跑起来

需要 Xcode 26 / iOS 26,以及旁边有一份 [aikitswift](https://github.com/zjywill/aikitswift)
的 checkout(云端请求走它):

```bash
git clone https://github.com/zjywill/aikitswift
git clone https://github.com/zjywill/HealthChat
cd HealthChat
```

两份 checkout 要**并排**放(`../aikitswift`)。然后生成工程并构建:

```bash
brew install xcodegen
xcodegen
xcodebuild -project HealthChat.xcodeproj -scheme HealthChat -destination 'platform=iOS Simulator,name=iPhone 17' build
```

`project.yml` 是工程的唯一事实来源,增删文件后要重新跑 `xcodegen`,不要手改 `.xcodeproj`。

第一次打开 app:设置页里选 provider 和模型(默认 anthropic / claude-sonnet-5,目录里有几十家
可选,只列支持工具调用的模型),填上那家的 API key。然后回到聊天界面授权 Apple Health。

模拟器里没有健康数据,开发者页面有一个生成模拟数据的按钮。

## 代码结构

`AgentRuntime` 是仓库内的一个本地 SwiftPM 包,**不 import 任何模型 SDK,也不认识 HealthKit**。
它只认两个协议——「一个能估 token、能流式跑一轮的模型」和「一组 JSON Schema 加一个执行闭包」
——在这两者之上跑工具循环,并负责上下文预算、压缩和失败重试。app 侧提供这两个协议的实现。

```
AgentRuntime/          通用 agent core(工具循环、上下文预算、压缩、重试、hook)
HealthChat/
  Chat/                聊天界面、会话列表与存储
  Engine/              AIKit 适配、健康工具、system 段拼装
  Health/              HealthKit 只读查询、触发点判定、check-in 排程
  Vision/              本机 OCR、PDF / docx / txt 取文本
  Medications/         用药与补剂
  Memory/              长期记忆
  Recall/              跨会话召回、后台派生的那几轮
  Search/              网页搜索
  Location/            粗定位
  Tenant/              家庭成员(目录级隔离)
  Intents/             Siri
  Settings/            provider / 模型 / 人格 / 开关
HealthChatTests/       app 侧集成测试
```

设计上的取舍和每一处「为什么是这样」写在 [CLAUDE.md](CLAUDE.md) 里,用药那块另见
[MEDICATIONS.md](MEDICATIONS.md),任务拆分见 [PLAN.md](PLAN.md)。

## 故意不做的

- **不做提醒和打卡**。Apple Health 从 iOS 26 起就有完整的用药追踪了,做第二套只会两边对不上,
  而在这里漏一次提醒的代价是真的。
- **不做本地交互作用数据库**。那是给一个 Vana 兜不住的结论背书。按一般知识说注意点、把结论
  指向药师,是这里唯一诚实的形态。
- **不做多设备同步和家庭共享账号**。要后端,而且把全家人的健康数据放上一台服务器是另一个
  量级的承诺。
- **不做端上模型**(曾经有过,体验没到可用标准,先撤了)。
